# Read-only plan Knowledge dependency review — partial AM-05.03

`reviewPlanKnowledge(context, knowledge, planning, selectedPlanRef)` is exported from `@accountability/factual-investigation/knowledge-review`. It uses actual pinned Knowledge inspection and existing Factual inspection, requiring the same trusted host research role/scope. Select an exact stored plan edition. The private detached result contains selected/latest plan refs, distinct basis/hypothesis claim roots, edition nodes and typed edges. It includes no source text, actor/time assertions, permission decision, answer or closure status.

Each node compares the exact captured ref to the latest logical kind/ID in the supplied scoped snapshot: `current-edition`, `changed-edition` or `missing-edition`. A missing captured edition may still expose an observed latestRef; null means no logical record in this snapshot. Neither missing status nor null proves real-world absence, deletion or lack of evidence. An empty root list produces an empty graph, not a satisfied investigation.

Traversal follows captured claim subjects, relationship from/to endpoints and event entity refs. It never substitutes children from a newer revision. Both older and newer editions can appear if deliberately captured through different paths. Roots/nodes and identical typed edges are deduplicated; differing edge types remain distinct. Only the reachable graph is returned. Unrelated snapshot records are validated but do not join it. All selected editions remain unchanged; no persistent review or automatic invalidation is written.

The full owning histories are validated before traversal. Limits256 distinct exact-edition nodes/512 distinct typed edges; expansion fails with review_full and returns no partial report. Existing2MiB planning and Knowledge bounds,128-ref upstream fields and2048 Knowledge revision cap still apply. Host ingress/CPU/heap/access limits remain mandatory; synchronous cloning/validation cannot be preempted and is not a sandbox.

This is a snapshot comparison, NOT current authentication, resource policy, consent/rights, evidence/source-content validation, truth or transitive permission. Even all current-edition nodes do not establish that a reported role is accurate, an investigation complete or a new action allowed. Historical selected plan versus latestPlan is explicit; consumers must not silently replace one. A supplied stale/partial Knowledge snapshot can only produce observations relative to itself. Hosts must obtain authorized current snapshots and separately perform relevant Evidence/Identity/consent/rights checks.

Seven initial neutral groups exercise actual relationship-backed plans, transitive endpoint changes, missing exact vs logical refs, explicit historical plan selection, unrelated exclusion, malformed/foreign/unauthorized input, copies and exact256-node/512-edge boundaries. No new SQL/network/provider/browser/AT/live qualification. This is not the complete AM-05.08 cross-engine correction-impact system: findings, evidence changes, efforts, creative outputs and releases are not traversed. AM-05.03 remains partial; evaluated answers, durable owning DB/audit/idempotency, authorized UI and deployed current policy remain pending. PAM stays at foundation; sending/publication/payments remain disabled.
